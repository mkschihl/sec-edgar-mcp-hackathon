The Problem SEC EDGAR Facts Explorer
Problem Statement

Financial data is authoritative — but AI doesn't use it

The SEC's EDGAR platform publishes free, machine-readable financial data for every public company in the United States. It is the most authoritative source that exists. Yet almost every financial AI workflow ignores it.

❌ The status quo

  • Financial chatbots answer from training data — stale and unverifiable
  • No path back to the primary source document
  • Hallucinated values look identical to real ones
  • Expensive third-party data vendors required for verified data

✓ What this project does

  • Calls the SEC's APIs directly — every answer is live data
  • Every number includes the accession number of the filing it came from
  • Every URL is a tool-returned EDGAR link — never constructed by the agent
  • No third-party data vendors, no API keys required for EDGAR
Core question: Can a watsonx Orchestrate agent answer real financial questions by querying the SEC's authoritative APIs directly — with every number traceable back to the SEC filing that reported it? Answer: yes — 39/39 benchmark questions, 100% pass.

System Design

Three connected layers

Layer 1 — MCP Server

Key Technical Decisions SEC EDGAR Facts Explorer
Engineering Choices

Six decisions that made it work

1. Remote MCP over stdio

The toolkit runs as a persistent HTTPS service on Code Engine, not as a subprocess inside WXO. Result: always-warm, independently versioned, reachable by any MCP client.

2. Duration-based quarterly filter

The SEC XBRL API stores 3-month and 9-month values under the same fp=Q3 label. Fix: compute end − start and accept only 80–100 day windows. Without this, Q3 Apple revenue reads $364B instead of $109B.

3. Q4 derivation

Companies don't file a 10-Q for Q4. The server derives Q4 = annual FY − nine-month YTD for USD flow concepts. Derived rows carry derived: true and reference both source accession numbers.

4. Server-side revenue concept selection

Apple uses RevenueFromContract...; Pfizer uses Revenues. The server evaluates all REVENUE_CANDIDATES and picks the concept with the newest period-end date. Always returns the right value.

5. EDGAR URLs from tool return values

Every fact row includes a filing_index_url computed from the accession number and CIK. Agent instructions prohibit constructing or guessing URLs; every link must come from a tool return value.

6. In-process XBRL concept resolver

sec_edgar_resolve_xbrl_concept builds an inverted index of all 7,462 FASB US-GAAP 2026 concepts at import time. Canonical overrides for derived metrics (ROE, EBITDA, D/E ratio). Zero network calls.

IssueSeverityRoot CauseFix

YTD values as quarterly figures (Apple Q3 ~$364B instead of ~$109B)HighEDGAR stores 3-month and 9-month values under same fp=Q3 label80–100 day duration filter; deduplicates per (start, end) pair

Next Steps SEC EDGAR Facts Explorer
Future Work

Where this goes next

Near-term improvements

  • International registrant support — foreign private issuers file on Form 20-F, not 10-K; FPI detection path needed
  • Extend XBRL concept resolver to cover the DEI taxonomy for entity-level facts
  • Streaming response mode for large 10-K text retrieval
  • Cache companyfacts at the tool call level to survive agent restarts

Longer-term extensions

  • Peer-company benchmarking — given a company and a metric, automatically find the 5 closest SIC peers
  • Trend detection — flag when a metric crosses a threshold for 3+ consecutive quarters
  • Extend Phoenix evaluation to cover the full 39-question suite with the production WXO agent as a regression gate
  • Publish the MCP server as a standalone open-source package
What this proves: Public government financial data, structured MCP tooling, and a well-instructed WXO agent can together answer verifiable financial questions with zero hallucination risk on the instrument-level data. Every answer has a primary-source citation. The evaluation methodology can serve as a template for evaluating financial-data AI agents.
