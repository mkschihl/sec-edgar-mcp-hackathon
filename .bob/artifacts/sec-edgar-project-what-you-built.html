SEC EDGAR Facts Explorer

What you built — a plain-language guide to the full hackathon project

The Big Picture

You built a system that lets an AI assistant answer questions about public company SEC filings — things like "What was Apple's revenue last quarter?" or "Which filing first reported Microsoft's most recent net income?" — by going directly to the SEC's official database, not by guessing from training data.

The system has three layers, built in order:

Layer 1 — The Tools (MCP Server)
8 functions that know how to talk to the SEC's APIs
↓
Layer 2 — The Agent
An AI that decides which tools to call and how to explain the results
↓
Layer 3 — The Evaluation
A test suite that measures whether the agent gives correct, useful answers

Layer 1 — The MCP Server (sec_edgar_tools)

Yes — the toolkit is the MCP server. MCP stands for "Model Context Protocol," which is an open standard for giving AI models access to external tools. Think of it like a power strip: you plug in functions, and any AI that speaks MCP can use them.

You built 8 tools, each of which wraps one type of SEC EDGAR API call:

#Tool nameWhat it does (plain English)
1search_companiesFind companies by partial name ("Berkshire" → returns BRK-A, BRK-B)
2resolve_companyLook up a company by ticker or CIK — returns full details (SIC code, state of incorporation, etc.)
3get_recent_filingsList the most recent 10-K, 10-Q, or 8-K filings for a company
4get_company_factGet a time-series of annual financial data — e.g. "Apple's net income for each of the last 8 fiscal years"
5get_quarterly_factsSame as above but for individual quarters (Q1/Q2/Q3/Q4 only, not year-to-date)
6compare_companiesCompare the same financial metric across multiple companies side-by-side
7get_filing_metadataLook up a specific filing by its accession number — returns form type, date, and a direct link to the SEC website
8list_conceptsDiscover what financial data tags (XBRL concepts) a company reports, so you can find the right one to query

The server runs as a containerised web service on IBM Code Engine (IBM's serverless container platform) and is always available at a public URL. It calls the SEC's public APIs — no login required, all public data.

What is XBRL?

XBRL (eXtensible Business Reporting Language) is a standardised tagging system the SEC requires public companies to use in their financial filings. Instead of just a PDF number, each figure like "net income" gets a machine-readable tag like NetIncomeLoss. This is what makes it possible to programmatically retrieve Apple's revenue without scraping a PDF.

Layer 2 — The Agent (sec_edgar_agent)

The agent is an AI that sits in front of the tools and handles the conversation with the user. Here is what it does that the tools alone cannot:

1
Understands natural language
A user says "Show me Apple's quarterly revenue." The agent figures out that means: call get_quarterly_facts with AAPL, us-gaap, RevenueFromContractWithCustomerExcludingAssessedTax. The user doesn't know (or care) what XBRL tag Apple uses.
2
Chains multiple tools together
"I don't know the ticker — find companies with 'Pfizer' in the name, then show me their last 4 annual revenues." That requires two tool calls in sequence: search first, then retrieve. The agent handles this automatically.
3
Formats and explains the results
Raw SEC data is numbers and accession codes. The agent turns "$94,000,000,000" into "$94.0 billion", adds fiscal year labels, presents comparison tables, and flags fiscal year misalignments ("Apple's year ends in September; Microsoft's ends in June — these figures may not be directly comparable").
4
Recovers from errors gracefully
If a concept name fails, the agent tries an alternate name or calls list_concepts to find the right one — rather than just saying "I couldn't find that."

The agent lives inside IBM watsonx Orchestrate (IBM's AI agent platform). It is accessible via the watsonx Orchestrate chat UI, via the REST API, or via the CLI. Any of those interfaces can send a question and get back an answer.

Could other agents or tools use sec_edgar_agent?

Yes. Because the agent is registered in watsonx Orchestrate, it can be used as a collaborator by other agents. A higher-level "financial research" agent could delegate SEC-related questions to sec_edgar_agent automatically. The MCP server can also be connected directly to any MCP-compatible AI client (Claude Desktop, other orchestration platforms, etc.) without the watsonx Orchestrate layer at all.

Layer 3 — The Evaluation Harness

A harness is a testing framework — the word comes from physical test harnesses in engineering (the cables and fixtures that hold a component in place while you measure it). A software test harness is the scaffolding that runs your system under controlled conditions and measures the results.

You built two evaluation harnesses, one after the other:

Harness 1 — REST-based tool-routing evaluator (evaluation/run_evaluation.py)

This one sends 20 carefully designed questions to the live agent via the watsonx Orchestrate REST API and checks: did the right tools fire? It doesn't judge the quality of the answer — only whether the correct SEC API calls were made. Result: 20/20 pass on 2026-11-07.

Harness 2 — Phoenix LLM-as-judge evaluator (eval/phoenix/)

This one measures actual answer quality — not just which tools fired, but whether the numbers are correct and whether the response is in-scope. It uses a second, independent AI model (a "judge") to read each response and score it. This is called "LLM-as-judge."

Why use an AI to judge an AI?

Human review of 20 questions is feasible. But if you wanted to test 500 questions, or re-run the test every time you make a change, human review doesn't scale. An LLM judge can evaluate a response in seconds and apply a consistent rubric. The key is using a different model as the judge than the one being tested — this reduces "self-preference bias" (a model tends to think its own answers are correct).

Status: The Phoenix harness is fully built and import-tested. It is waiting on one thing: the USAI model gateway credentials from the GSA hackathon lab portal, which provide access to the AI model the harness uses as a judge.

What the Human Audit Found

Between the two automated harnesses, you read all 20 agent responses yourself and found real issues the automated scorer missed. The most important ones, now fixed:

  • YTD values returned as quarterly figures — Apple's "Q3 revenue" was showing $364B (nine months) instead of $109B (three months). Fixed in the server by filtering on observation duration.
  • Wrong company selected for ExxonMobil — the search returned a holding-company shell with no filings instead of the main operating entity. Fixed in the agent instructions.
  • Concept synonyms missing — "revenue" searches missed many revenue-related XBRL tags that don't contain the word "revenue." Fixed in the agent instructions.
